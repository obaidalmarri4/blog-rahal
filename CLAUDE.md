## Commands
- `npm run dev` — development server (astro dev)
- `npm run build` — build for production. With the Vercel adapter the result is `.vercel/output/` (static files in `.vercel/output/static`, one function in `functions/_render.func`); `dist/` is only an intermediate.
- `npm run preview` — serve the built `.vercel/output` locally on :4322 the way Vercel routes it (`scripts/lib/vercel-output-server.mjs`; `astro preview` does not work with the Vercel adapter). Set `STUDIO_KEY` to try the studio.
- `npm run build && node scripts/studio-access-check.mjs` — access gate for the owner studio (see Gotchas).
- `node scripts/studio-editor-check.mjs` — editor gate (no build needed): every post opens and saves through the editor and is accepted by the server check; partial deletes lose nothing else; hostile input is rejected; paste comes in clean. Run it with `studio-roundtrip.mjs` after touching the schema, `document.js`, `paste.js`, `raw-blocks.js` or `sanitize.ts`.
- `npm run build && node scripts/studio-write-check.mjs` — write gate: runs the built bundle against an in-memory GitHub and an in-memory Blob and checks exactly what each studio action commits or uploads (metadata, body, delete, new post, image upload). Needs no token and touches no real repository or store.
- Deployed on Vercel (production alias): `https://blog-rahal.vercel.app`

## Conventions
- **Content is Arabic and RTL** — do not translate, reverse, or reorder Arabic text. Preserve direction as-is.
- Fonts: Thmanyah Serif Display is self-hosted as woff2 under `public/fonts/`; Amiri, Reem Kufi, Cormorant Garamond, and JetBrains Mono load from Google Fonts via `BaseLayout.astro`. Post bodies must always render in Thmanyah — the sanitizer strips `font-family` overrides from `content_html` (see `scripts/sanitize-posts.cjs`).
- Use the helpers in `src/utils/posts.ts` for data access — do not read the JSON files directly in pages.
- Styling via Tailwind 4 (utility classes) + `src/styles/global.css`; there is no `tailwind.config` — it's configured through `@tailwindcss/vite` in `astro.config.mjs`.

## Routing & content
- File-based routing. Dynamic pages use `getStaticPaths` (static site / SSG).
- Post URLs: `blog/[slug].astro` builds params from `getPostSlug(post)` (strips `.html`, converts `/` to `-`).
- Posts = 400 JSON files in `src/content/posts/`, read via `import.meta.glob` in `posts.ts`. **No content-collection config** — this is a custom system, do not assume `astro:content`.

## Gotchas
- **`src/data/taxonomy.json` must stay in sync with the posts.** It is auto-generated by `scripts/classify-posts.py` (reads `src/content/posts/*.json` and outputs the classification: continent / countries / type). If you add posts, regenerate it instead of hand-editing.
- The classification key in `taxonomy.posts` is the slug (output of `getPostSlug`) — it must match, otherwise the post won't appear on continent/country pages.
- A post's `type` is either `travel` (has continent/countries) or `other` (has `category`). Destination pages show only `travel`; `destinations/other.astro` shows the rest.
- **New posts arrive automatically and unclassified.** `.github/workflows/sync-blogger.yml` runs `scripts/sync-blogger.mjs` every 3 hours and commits anything newly published on `rahal-k.blogspot.com` straight to `main` (Vercel then deploys). Those posts have no key in `taxonomy.posts`, so they show in `/blog`, the homepage, the album and their own page, but not on continent/country pages until their key is added. `git pull` before working — the bot may have pushed.
- **Post bodies must not carry inline base64 images.** Blogger lets the author paste images straight into a post, which stores them inside `content_html` (one post reached 43MB). `node scripts/extract-inline-images.mjs` moves them to `public/media/posts/<slug>/` and is safe to re-run; run it if a synced post arrives with `data:image/` in it.
- **One slug = one file.** Astro silently builds only the last file (alphabetically) when two posts share a slug.
- **The post body has one path in and out of the editor: `src/lib/studio/document.js`** (`loadBody` = two parse passes → canonical document; `bodyForSave` → HTML). The browser editor and the gates call the same functions with different DOMs. Don't use TipTap's string `content` option or `editor.getHTML()` — they parse differently and what gets saved would stop matching what the gates prove.
- **The server never stores body HTML it has not checked (`src/lib/studio/sanitize.ts`): allowlist, reject-don't-clean.** Outside preserved blocks only the tags/attributes the schema emits are accepted; a preserved block (table, iframe, video…) is accepted only if that same block already exists in the stored post. Adding a mark, node or attribute to the schema means adding it to `ALLOWED` there too, or every save containing it is refused (422) — the editor gate catches the mismatch. What is stored is parse5's serialization of the checked tree.
- **Preserved legacy blocks cannot be created in the editor, only moved or deleted.** Pasted tables are flattened to paragraphs (`paste.js`) for that reason. New embeds (YouTube) arrive in phase 4 with their own narrow rule.
- **First save of an old post rewrites its whole body into the editor's canonical form:** Blogger wrappers, inline margins, `float`, `line-height`, link classes and `dir="ltr"` on wrappers are dropped; text, images, links, tables and embeds are kept (that is what the round-trip gate proves). `images[]` changes only for images actually removed or added (`reconcileImages` in `scripts/lib/post-html.mjs`).
- **`\uXXXX` escapes typed into a file through the agent's write tools can land as the literal character** (a raw U+2028 inside a regex breaks the file). After writing code that contains such escapes, check the file; build them with `String.fromCharCode` or write them via a script.
- **Editor schema changes must pass the round-trip gate:** `node scripts/studio-roundtrip.mjs` pushes every post through `src/lib/studio/schema.js` and fails if any text, image, link, embed or table is lost. Don't swap the custom `fontSize`/`textColor`/`highlight` marks for TipTap's `TextStyle` extension — its nested-span merging grows exponentially on Blogger HTML.
- **Owner studio (`/studio`) — private page for the blog owner, no login by the owner's decision.** Access = a secret link `/studio/enter/<STUDIO_KEY>` that sets a signed pairing cookie and redirects to `/studio`; everyone else gets the normal 404 page. `STUDIO_KEY` is a Vercel env var (Production only; ≥32 URL-safe chars; locally in the git-ignored `.env.local`). No key, a Preview deployment, or an untrusted host ⇒ the studio answers 404 to everything. Changing the key revokes the link and every paired device. Whitespace around the stored value is trimmed (a paste into Vercel can carry a newline); a missing or unusable key on Production writes one `[studio] …` line to the Vercel runtime logs — the only place that tells "studio off" apart from "wrong link", since visitors always get the same 404.
- **Every route under `/studio` and `/api/studio` must** `export const prerender = false`, start with `requireStudio(...)` from `src/lib/studio/guard.ts`, and never return a 404 with an empty body (Astro would fetch `/404.html` over the network to fill it). **After touching `src/middleware.ts`, `src/lib/studio/{session,access,guard}.ts`, any studio route, or the adapter config, run `npm run build && node scripts/studio-access-check.mjs`** — it runs the real production bundle and fails if the studio opens without a valid pairing.
- **The studio has no database — it writes to this repository through the GitHub API** (`STUDIO_GITHUB_TOKEN`: fine-grained, this repo only, Contents read/write + Commit statuses read). Every write is one atomic commit conditioned on the branch head it read (`expectedHeadOid`); if the branch moved (the sync bot, another device) it re-reads and re-applies. Keep that pattern: read a snapshot → change what was read → `createCommit` → retry on `StaleHeadError`. GitHub reports a moved head in two shapes, both mapped to `StaleHeadError` in `github.ts`: `STALE_DATA` (the branch moved before the request arrived) and `FORBIDDEN` with the message `is at <oid> but expected <oid>` (two writes raced — seen on the real repository, 2026-11-21); any other `FORBIDDEN` is a real permission refusal and is not retried. Reads are repeated once on 502/503/504; the commit mutation never is (a 5xx does not say whether the commit landed). After touching `src/lib/studio/{github,store,taxonomy,validate,config}.ts` or a studio page, run the write gate.
- **Which branch the studio writes to:** `main` only on Vercel Production. Anywhere else the default is `studio-sandbox` (override with `STUDIO_BRANCH`), so a local run never reaches the live site by accident. `vercel.json` turns off Vercel deployments for `studio-sandbox`.
- **New posts from the studio (`/studio/new` → `POST /api/studio/posts`, `createPost` in `store.ts`).** Slug `YYYY-MM-rk-<6 chars>`: the post date's month + an id the browser generates once per draft and keeps in the IndexedDB draft; a repeated publish with the same id (double tap, lost response) answers 409 with the existing slug instead of creating a twin. File `NNNN_<slug>.json`, NNNN = highest prefix on the branch + 1, recomputed on every retry (the sync bot numbers the same way, so a race only shifts the number). Fields in the sync's order plus `url: ""` and `source: "studio"`. Blogger slugs never contain `rk-`, so the two cannot collide.
- **Editor images go to Vercel Blob (public store) through `POST /api/studio/media`.** The browser downsizes each photo to a ≤2000px JPEG + a 480px JPEG (`src/scripts/studio/images.ts` — wait for the image `load` event, not `img.decode()`: on a post page with dozens of images Chrome left `decode()` pending forever and uploads hung). The server checks both are JPEG within limits (`media.ts`, header parsed by `jpeg.ts`) and writes `posts/YYYY/MM/<id>.jpg` + `-thumb.jpg` (`sandbox/…` when not publishing to the live site). The editor inserts `<img src=full data-thumb=thumb>`; `extractImages` (via `isSiteImage`) turns that into the `images[]` entry, so the first uploaded image becomes the cover. Needs `BLOB_READ_WRITE_TOKEN` (or `BLOB_STORE_ID` with OIDC on Vercel), added when a Blob store is connected to the project; without it the page renders `data-media="off"` and the image button says upload is off. An image whose post is never saved stays in Blob unreferenced.
- **`src/scripts/studio/editor.ts` calls `start()` at the bottom of the file on purpose.** In `new` mode `start()` runs synchronously up to its first `await` and needs every module-level `const` above it; calling it at the top threw a TDZ `ReferenceError` and the editor never mounted.
- **`src/data/removed-posts.json` is the studio's deleted-posts list.** A delete removes the post file, removes its `taxonomy.posts` key and appends a record there, in one commit. `scripts/sync-blogger.mjs` treats those slugs as existing — without the record a deleted Blogger post comes back within 3 hours. Don't remove records by hand unless the post should be re-imported.
- **The studio edits `taxonomy.json` in place** (one key, appended at the end when new, everything else byte-identical) and applies only the form fields the user actually changed. Regenerating the file with the classifier scripts would discard those edits.
- **Studio list = build-time index + live diff.** `virtual:studio-index` (title/date/… and the git blob id of every post, built by `src/lib/studio/index-plugin.mjs`) ships inside the function; at request time the studio compares blob ids with the branch tree and fetches only files that changed since the build. Don't import `getAllPosts()` from studio code — it would bundle every post body into the function.
- **`security.allowedDomains` in `astro.config.mjs` must list every host the site is served on.** Without a match Astro replaces the host with `localhost`, and the studio refuses the request (by design). Add a custom domain there when one is connected.
- **Studio responses use `Referrer-Policy: same-origin`, not `no-referrer`.** With `no-referrer` browsers send `Origin: null` on same-site POSTs and every studio form/button fails the Origin check with 403.
- **`security.checkOrigin` is off on purpose (`astro.config.mjs`).** Astro's built-in check runs before the middleware and answers 403 «Cross-site POST form submissions are forbidden» to any unsafe request without a matching Origin — even from an unpaired visitor — while unknown paths answer 404, which revealed that `/studio` exists (seen on the live site). The middleware's own check (Sec-Fetch-Site + Origin, every unsafe method of a paired device) replaces it; the access gate covers both sides. Don't turn it back on.
- **`NotFoundPage.astro` must render byte-identically from `404.astro` (static) and `studio/not-found.astro` (server)** — no props, nothing read from the request. A difference reveals that the studio exists.
- **Public pages must stay prerendered.** The middleware answers 404 to any non-studio on-demand request (that closes Astro's `/_image` and `/_server-islands` endpoints, unused here). A new server-rendered feature outside `/studio` needs that rule revisited.
- Backup files exist in the repo (`index.astro.backup-quotes-organized` and others) — ignore them, they are not live routes.
